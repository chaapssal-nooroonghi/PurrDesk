## 빌드 환경 결과

Windows Server 2025 / WACK 10.0.26100.9457에서 전체 WACK 24 PASS / 0 FAIL / 0 WARNING, PARTIAL_RUN=FALSE. 테스트 복사본 설치·패키지 앱 ID 실행·두 귀염둥이 PMv2 창 확인. 6종 창/72개 글꼴 픽셀 검사 시나리오, 네 탭 전환, 새 창, 저장 전 이름/숫자 보존, 100% 복귀 후 버튼·행 잘림 검사 통과. 두 귀염둥이 메뉴를 실제로 열어 현재 화면의 Windows 기본 메뉴 글꼴 높이와 일치함도 확인했습니다.

이것은 실제 Windows 런타임에서 DPI 메시지와 그래픽 컨텍스트를 재현한 검사입니다. Cloud PC의 250→100% 전환, 혼합 배율 물리 모니터, 로그아웃 자동 시작을 대신하지 않습니다. 메뉴의 실제 배율 전환도 Cloud PC에서 확인해야 합니다.

## 이전 검사가 놓친 부분

1.0.9의 검사는 주로 DeviceDpi와 Font.SizeInPoints를 비교했습니다. 같은 point 값도 글꼴 변환 장치 컨텍스트 DPI에 따라 픽셀 높이가 달라질 수 있습니다. 또한 비활성 탭은 아직 HWND가 없어 자식 DPI 알림을 못 받을 수 있습니다. 첫 탭만 정상인 실제 경로를 기존 검사가 충분히 재현하지 못했습니다.

이번에는 96/240 DPI 컨텍스트에서 LOGFONT 픽셀 높이를 읽고, 비활성 탭의 핸들을 먼저 만들지 않은 상태에서 DPI를 바꾼 뒤 다른 탭을 선택합니다. 기존 1.0.9에서 오류를 재현했고 수정본은 이 검사를 통과했습니다. 실제 Cloud PC의 GDI+ 장치 컨텍스트 값을 직접 측정한 것은 아니므로 최종 해결은 아래 실제 경로 재검사로 판단하세요.

## 핵심 재검사 순서

1. 기존 환경 유지 지시에 따라 현재 설치·프로세스·인증서 유효기간·권한부터 확인하세요. 이 전달문 때문에 기존 앱·인증서를 삭제하거나 권한을 재설정하지 마세요. 원본 해시를 대조하고 복사본만 테스트 서명하여 기존 1.0.9.0 위에 업데이트 설치하세요. 숨김 사용자 데이터를 포함한 백업과 사진·설정 해시를 보존하세요.
2. 실제 250%에서 앱과 설정창을 열고 첫 탭에서 이름을 저장하지 않은 채 수정하세요. 앱과 설정창을 계속 켠 상태로 100%로 바꾸세요.
3. 첫 탭뿐 아니라 **시간·알림 → 모습·사진 → 표시·실행 → 첫 탭** 순서로 선택하고 글꼴·버튼 글자·스크롤 끝·입력 보존을 확인하세요.
4. 취소 후 **같은 프로세스에서 우클릭 메뉴 → 새 설정창**을 열어 크기를 확인하세요. 귀염둥이 메뉴와 트레이/하위 메뉴를 모두 확인하세요. 문제 화면에서 모니터 배율과 HWND DPI를 따로 측정하세요.
5. 이어서 250→200→150→125→100% 및 역순, 각 배율 새 실행, 크기/뽀모도르/스트레칭/사진 관리 창, 말풍선·드래그·클릭 통과·숨김을 확인하세요. 저장 전 숫자/시간 값이 유지되는지도 보세요.
6. 실제 로그아웃·재로그인 자동 시작을 확인하세요. 수동 실행과 자동 실행을 구분해 시각·프로세스 경로를 기록하고 설정·사진 해시를 대조하세요.
7. Cloud PC WACK 10.0.28000.2957에서 공식 `-appxpackagepath` 전체 검사로 재검증하세요. 원본 XML의 전체 결과와 24개 TEST 결과를 읽으세요. 물리 혼합 배율 모니터를 검사하지 못하면 미검사로 명시하세요.
