## 변경 및 확인된 범위

- 새 대화상자의 배치 전에 실제 HWND DPI와 Framework DeviceDpi를 동기화합니다.
- 화면 표시 설정 변경/창 활성화 때 배율을 확인하고, 모니터와 HWND의 DPI가 어긋난 경우에만 HWND를 재생성합니다. 기존 컨트롤·저장 전 입력값을 유지합니다.
- 배율 축소 때 잘린 경계가 최소 창 크기로 고착되는 것을 막습니다.
- 귀염둥이의 지정 픽셀 크기는 유지합니다. 말풍선 그림의 기준 해상도를 96 DPI로 고정해 시작 시점의 화면 DPI에 따라 글자만 커지는 것을 방지합니다.
- 1.0.8.0 대비 패키지에서 달라진 항목은 PurrDesk.exe, AppxManifest.xml과 패키징 메타데이터뿐입니다. 사진·ONNX 모델·기타 파일은 모두 바이트 일치했습니다.
- 기존 GitHub v1.0.5와 Mac 릴리스는 변경하지 않았습니다.

Windows 빌드 환경(Server 2025, WACK 10.0.26100.9457) 결과:
- WACK 전체 24 PASS / 0 FAIL / 0 WARNING, PARTIAL_RUN=FALSE.
- 복사본 테스트 서명 후 설치, 패키지 앱 ID 실행, 두 귀염둥이 창 PMv2 확인.
- 설정 네 탭과 크기/뽀모도르/스트레칭 창의 100/125/150/200% 레이아웃 스트레스 검사 통과.
- 6종 창의 72개 DPI 회귀 시나리오에서 관리 DPI·본문/자식 글꼴·저장 전 숫자 입력 보존 검사 통과.

회귀 검사는 실제 Windows 런타임에서 테스트용으로 오래된 Framework DPI 캐시와 WM_DPICHANGED를 재현한 것입니다. **실제 원격 Windows 배율 변경이나 물리 모니터 이동 검사를 대신하지 않습니다.** 빌드 환경에서는 로그아웃·재로그인 자동 시작도 검사하지 않았습니다.

## Cloud PC에서 할 일

1. 기존 1.0.8.0 설치·인증서·권한·실행 상태부터 확인하세요. 기존 환경 유지 지시를 따르고, 이 전달문 때문에 앱·인증서를 삭제하거나 권한을 바꾸지 마세요. 인증서 유효기간도 확인하세요.
2. 앱 종료 상태에서 기존 사용자 데이터의 **숨김 폴더까지** 백업하고 설정·사진 파일 해시 목록을 보존하세요. 1.0.8 검사에서는 숨김 CatDesk 데이터 백업이 빠졌습니다.
3. 다운로드 MSIX 해시를 위 값과 대조하고 복사본만 서명하세요. 동일 패키지 ID의 1.0.8.0에서 1.0.9.0으로 업데이트 설치해 설정·사진 보존을 확인하세요.
4. 배율 100/125/150/200/250%에서 각각 새로 실행하는 검사와, **앱을 계속 켠 채 배율을 오르내리는 검사**를 구별하세요. 핵심 재현은 250→100%, 그리고 250→200→150→125→100% 및 역순입니다. Chrome 확대율을 Windows 배율로 간주하지 말고 기존 도구로 모니터 배율과 HWND DPI를 별도 측정하세요.
5. 전환 전에 열어 둔 설정창과 전환 후 새로 연 설정창 모두 확인하세요. 네 탭·스크롤 끝·우클릭 메뉴·크기·뽀모도르·스트레칭 창·말풍선을 확인하고, 저장 전 이름/시간 입력이 유지되는지도 보세요. 귀염둥이 크기·드래그·클릭 통과·숨김/표시도 확인하세요.
6. 실제 로그아웃·재로그인 자동 시작을 확인하세요. 지연될 수 있으므로 수동 실행과 자동 실행을 구분해 시각·프로세스 시작 경로를 기록하세요. 사진 해시와 설정 비교도 남기세요.
7. 같은 Cloud PC의 WACK 10.0.28000.2957에서 공식 패키지 검사로 재검사하세요:
   `appcert.exe reset`
   `appcert.exe test -appxpackagepath <테스트서명_복사본.msix> -reportoutputpath <wack-report.xml>`
   원본 XML의 전체 결과와 24개 TEST 결과를 판정하세요. WindowsApps ACL 변경, 검사 제외·보고서 수정·패키지 컨텍스트 주입은 하지 마세요.
8. 혼합 배율의 실제 물리 모니터 간 이동이 가능하면 확인하고, 불가능하면 미검사로 명시하세요. 경고·실패·재현된 UI 문제가 남으면 제출하지 마세요. 이 빌드 세션에서는 제출하지 않았습니다.

결과는 짧은 보고서, WACK 원본 XML, 실패/전후 화면, DPI 측정값만 먼저 전달하면 됩니다. 이미 받은 MSIX 전체를 증거 ZIP에 다시 넣을 필요는 없습니다.
